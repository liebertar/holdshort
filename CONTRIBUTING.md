# Contributing

This is the whole process: how to set up, what to run before you push, and how a change reaches `dev` and
`main`.

## Set up

1. Requirements: Docker with Compose 2.24 or newer, or Python 3.12 with `pyyaml` to run without Docker;
   Node 22 for the map tests. Sizes are in the README's [requirements](README.md#requirements).
2. Clone, then create your local settings from the example:

   ```sh
   git clone https://github.com/vectordyne-temp/sky-net && cd sky-net
   cp .env.local.example .env.local
   ```

   Every value is optional. `.env.local` and `.env.dev` are ignored by git; never commit a key.
3. Run the stack with `make up` (Docker) or `./scripts/dev.sh` (no Docker). The map is at
   http://localhost:3100.
4. For the Python tests and lint without Docker: `python3 -m pip install pyyaml pymavlink ruff`. Without
   `pymavlink` the 27 MAVLink tests are skipped.

## Before you push

```sh
make lint                                    # ruff
make test                                    # Python suite, about 10 minutes
node --test tests/test_map.mjs               # map
docker compose -f docker-compose.local.yml --env-file .env.local.example config -q
```

CI (`.github/workflows/checks.yml`) runs the same on every pull request into `dev` and `main`.

## Branches and pull requests

- `main` is what we ship. Only `dev` merges into it, through a pull request with one approving review, with
  `dev` up to date and every check green.
- `dev` collects work. Cut a branch from it named `<type>/<topic>` (`feat/runtime-advisory`,
  `fix/briefing-paths`, `docs/readme`), push it and open a pull request into `dev` with the template filled
  in. Merge once the checks pass, with a merge commit so the branch's commits stay as they are.
- Never force-push, and never rewrite a commit that is already pushed.

## Commits

- Subject: `type(scope): short description` — English, lower case, no period, at most 72 characters. Types:
  `feat` `fix` `refactor` `docs` `test` `chore` `perf` `style` `ci`. The scope is the stack or module
  (`runtime`, `map`, `drone`, `sim`, `compose`, ...).
- Body: three to five `-` bullets, mostly about why. The history writes bodies in Korean.
- One logical change per commit; unrelated changes go in separate commits.
- No co-author or tool trailers, and no "generated by" lines, in commits, code or pull requests.

## Ground rules for the code

- One folder per stack (`frontend/` `backend/` `drone/` `shared/` `sim/`), each with its own Dockerfile and
  optional overlay. The root holds one compose file per environment.
- The runtime alone judges and commands. Models write forms, pick among legal candidates and read prose;
  they never decide a clearance.
- Rules that tighten apply at once; rules that loosen wait for a person or an expiry.
- Comments and docs are in English; the README also comes in Korean, Chinese and Spanish.
